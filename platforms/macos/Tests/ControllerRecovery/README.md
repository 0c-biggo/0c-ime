# Controller recovery regression

Run `make -C platforms/macos test-controller-recovery` on an Apple Silicon Mac. The harness compiles the production input controller and connects it to an isolated engine socket. It checks queued composition recovery and Caps Lock state synchronization after a warm IPC session fails. A second engine set to return to Zhuyin each time (`mode_memory=native`) with right Shift as the switch key checks that turning Caps Lock on and off returns to the mode from before it was turned on (#219). A stand-in app that, like Office and Terminal, hands arrow keys, Esc and Enter to the input method only while it has marked text checks the symbol menu opened without a composition (#283): a placeholder marked text is present, Down moves the highlight, Right turns the page, the same placeholder is not sent twice, Esc leaves nothing in the document, picking from the first tab (#290) and Enter insert only the symbol, and the placeholder is removed on `commitComposition` and `deactivateServer`. A stand-in app whose `markedRange` always returns NSNotFound checks that switching simplified output twice mid-composition (`simplifiedMenuAction`, the menu item and ⌃⇧F11) re-sends the composition each time without committing, and Enter then commits it (#347; before the fix this hit the `RequestQueue.present` precondition). A stand-in app that keeps the document text and caret (`CaretClient`) checks the digit-before-caret bit (#337): only the first key of a composition carries it (true after a 3 typed in ABC, false at the start of the document or after the text changed outside a composition, absent with a selection or when it cannot be read), and the English modes from Caps Lock and right Shift do not read it. It does not install or register an input method.
